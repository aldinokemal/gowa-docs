GOWA reads configuration from three places:

- **Command-line flags** on `whatsapp rest` (run `./whatsapp rest --help` for the full list).
- **Environment variables**.
- A **`.env` file** in the working directory (`src/.env` when running from source; copy `src/.env.example`).

The `.env` file only fills in variables that are not already set in the environment.

<Warning>
In the current code, environment variables (including `.env`) are applied **after** flags are parsed, so a variable that is set overrides the matching flag. MCP OAuth settings, `--allow-unauthenticated`, `--trusted-origins`, `--chatwoot-webhook-allow-unsigned`, and `--webhook-all-device-receipts` are exceptions whose explicit flags win. Set each option in one place only. For example, `WHATSAPP_WEBHOOK_INSECURE_SKIP_VERIFY=true` overrides `--webhook-insecure-skip-verify=false`.
</Warning>

Booleans accept `true`/`false`. Durations use Go syntax (`30s`, `5m`, `3h`). List values are comma-separated.

## Commands

| Command | Description |
|---|---|
| `whatsapp rest` | Start the REST API, dashboard, WebSocket and MCP endpoint. Required since v6; a bare `whatsapp` does not start the server. |
| `whatsapp version` | Print the version and exit. |
| `whatsapp --help` | List commands and flags. |

## Server

| Variable | Flag | Default | Description |
|---|---|---|---|
| `APP_PORT` | `--port`, `-p` | `3000` | HTTP port. |
| `APP_HOST` | `--host`, `-H` | `0.0.0.0` | Bind address. |
| `APP_DEBUG` | `--debug`, `-d` | `false` | Verbose logging. |
| `APP_OS` | `--os` | `GOWA` | Device name shown in WhatsApp's **Linked devices** list. |
| `APP_BASIC_AUTH` | `--basic-auth`, `-b` | — | Complete `user:pass` pairs, comma-separated. Required for a non-loopback listener unless the explicit unauthenticated override is set. |
| `APP_ALLOW_UNAUTHENTICATED` | `--allow-unauthenticated` | `false` | Permit a non-loopback listener without Basic Auth. Use only behind an authenticating proxy with restricted direct access. |
| `APP_TRUSTED_ORIGINS` | `--trusted-origins` | — | Exact extra browser origins allowed to mutate state and open WebSockets. The request host and specific CORS origins are also trusted. |
| `APP_BASE_PATH` | `--base-path` | — | Serve under a sub-path, e.g. `/gowa`. `/health` stays at the root. |
| `APP_TRUSTED_PROXIES` | `--trusted-proxies` | — | Proxy IP ranges whose forwarded headers are trusted, e.g. `10.0.0.0/8`. |
| `APP_CORS_ALLOWED_ORIGINS` | `--cors-allowed-origins` | — (any origin) | CORS origins. Specific origins also pass browser origin checks. A wildcard does not authorize mutations or WebSockets. |

## Storage

| Variable | Flag | Default | Description |
|---|---|---|---|
| `DB_URI` | `--db-uri` | `file:storages/whatsapp.db` | Session store: SQLite (`file:...`) or PostgreSQL (`postgres://...`). |
| `DB_KEYS_URI` | `--db-keys-uri` | same as `DB_URI` | Optional separate store for the encryption key cache. Avoid in-memory stores in production. |
| `CHAT_STORAGE_MAX_OPEN_CONNS` | — | `5` | Max SQLite connections for chat storage. Raise if sends time out under heavy inbound load. |

Chat storage (chats, messages, schedules) always lives in `storages/chatstorage.db` and is not configurable.

SQLite databases for sessions, chat storage, and OAuth are created with `0600` permissions. Directories GOWA creates for these files use `0700`. Existing directories keep their permissions. Permission changes that are not supported by the filesystem are logged as warnings.

For PostgreSQL session and key stores, an omitted or blank `sslmode` defaults to `verify-full` for remote dial targets. `localhost`, loopback IPs, and Unix sockets default to `disable`. Explicit URI settings, `PGSSLMODE`, and service configuration remain effective. A `PGSERVICE` entry can override the URI host and TLS mode. For managed PostgreSQL, supply `sslmode=verify-full` and the required CA configuration explicitly.

## Fixed limits

These are compiled in and cannot be changed by configuration:

| Limit | Value |
|---|---|
| Image upload | 20 MB |
| Document upload | 50 MB |
| Video upload and HTTP request body | 100 MB |
| Incoming media download | 500 MB |
| Request timeout | 45 s (`504 GATEWAY_TIMEOUT`) |
| Webhook delivery | 10 s per attempt, 5 attempts |

## Media URL downloads

Send requests that fetch media, documents, or link previews accept HTTP and HTTPS URLs. Public URL fetches reject loopback, private, link-local, metadata, multicast, and reserved destinations. Redirects and the address actually dialed are checked. These downloads connect directly and do not use `HTTP_PROXY` or `HTTPS_PROXY`.

GOWA can read its own `/statics` URLs from disk. Chatwoot attachment downloads can use the configured Chatwoot destination or allowed hosts, including an internal host when trusted through that integration. This exception does not apply to arbitrary URLs submitted to the send API. Use file uploads when the source is private.

## Not used

`src/.env.example` lists `WHATSAPP_WEBHOOK_INCLUDE_OUTGOING` and `WHATSAPP_CHAT_STORAGE`, but the current code does not read either. Setting them has no effect.

## Example

```bash .env
APP_PORT=3000
APP_OS=MyCompany
APP_BASIC_AUTH=admin:a-long-random-password
APP_TRUSTED_PROXIES=10.0.0.0/8
DB_URI=postgres://gowa:replace-with-password@db.example.com:5432/gowa?sslmode=verify-full
WHATSAPP_WEBHOOK=https://example.com/wa-hook
WHATSAPP_WEBHOOK_SECRET=another-long-random-secret
WHATSAPP_WEBHOOK_EVENTS=message,message.ack
WHATSAPP_AUTO_MARK_READ=false
```

Equivalent flags:

```bash
./whatsapp rest --port=3000 --os=MyCompany \
  --basic-auth=admin:a-long-random-password \
  --webhook=https://example.com/wa-hook \
  --webhook-secret=another-long-random-secret \
  --webhook-events=message,message.ack
```
